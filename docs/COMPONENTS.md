# hodos — Component Specifications

One entry per component. Each entry is the contract the builder implements and the reviewer checks against. File shapes are in `FORMATS.md`; writing rules in `AUTHORING.md`; rationale in `DESIGN.md`.

Every entry has: **Purpose · Invocation · Inputs · Outputs · Procedure · Completion · Anti-pattern · Limits · Depends on**.

Shorthand: `ledger.mjs add …` means `node ${CLAUDE_PLUGIN_ROOT}/scripts/ledger.mjs add …`. Scripts are always invoked by that absolute form; the bare name is documentation shorthand only.

## 1. Skills

Every kernel opens with `` !`node ${CLAUDE_PLUGIN_ROOT}/scripts/state-digest.mjs` `` so the project state is present before the first reasoning step, and carries `allowed-tools: Bash(node ${CLAUDE_PLUGIN_ROOT}/scripts/*)` (`PLATFORM-NOTES.md` check J covers the expansion of that pattern). A kernel that needs another skill's procedure invokes that skill through the Skill tool, which is why its target is model-invocable (`PLATFORM-NOTES.md` check H, decision 0016). Reproducing another skill's procedure inline is forbidden: it duplicates the invocation contract at the call site and drifts from it.

### 1.1 `task` — S1 kernel

**Purpose.** Own session 1: route the request, research if needed, grill and plan, obtain approval, hand off to S2. The exception is an `inert` verdict that finishes as one, whose whole task runs in S1 with no S2 (decision **0183**). One upgraded out of the shape is re-planned and handed off like any task (decision **0184**).
**Invocation.** `/hodos:task <description>` · `/hodos:task <campaign>/<node>` to start a campaign node.
**Inputs.** The description; `config.json`; campaign maps in scope; existing task dirs.
**Outputs.** `tasks/<slug>/{brief,research,plan}.md`, `ledger.md`, `state.json` (phase `approved`), and the task pointer — `.claude/hodos/sessions/<session-id>`, or `active` where no session id is reachable — written by `ledger.mjs init` (decisions 0047, **0171**); the printed handoff line. An `inert` task that finishes as one prints no handoff line (decision **0183**). It leaves the task's commit, `evidence/`, `review.md` while the review runs, `plan.md#Outcome`, the history line and phase `done`. After `Upgrade: inert→quick`, the task instead leaves the revert of its commits, and then, as on any path, a full plan approved on the same branch and the handoff line (decision **0184**).

**Procedure (standing).**
1. `config.mjs find`; `notFound` → say "run `/hodos:init` first" and stop (hard dependency).
2. Read `references/route.md`; fill the nine-row checklist with evidence; derive the verdict by the rules in `FORMATS.md §3`; `AskUserQuestion` with the proposed path/type/campaign and the alternatives. On a verdict of `quick`, `standard` or `deep`: derive the slug; `ledger.mjs init <slug> --path <p> --type <t> [--shape <s>] [--campaign <c/n>]`; write `brief.md`. A campaign verdict opens no task — `ledger.mjs` records a path out of `quick|standard|deep` and a campaign has no path of its own (`FORMATS.md §3`, decision 0031) — so this step is skipped and the printed, confirmed verdict is what step 3 hands over.
3. Campaign verdict → invoke the `campaign` skill through the Skill tool (decision 0016); stop when it returns. Invoked as `<campaign>/<node>` this step is skipped — a node is already scoped, and skipping it is what terminates the `task` → `campaign` → `task` re-entry.
2i. A `quick` verdict confirmed with `Shape: inert`, whose one question also approved the short plan: read `references/inert.md`, which replaces steps 4–8 in this session with the short plan, the edit, the two commands, one commit, one fresh review and `finish`, and prints no handoff (decision **0183**).
4. Type `question` → answer with sources in chat; `ledger.mjs add "Finish: report delivered"`; stop. No plan.
4b. Type `bug` and no candidate from step 2 is a command that fails as the repository stands: read `references/reproduce.md` and take one of its two exits before any plan exists. Exit A writes a `## Reproduction` block into `brief.md` whose command is T1 of the plan; exit B writes one `Ruling: not reproducible here — …` and **no plan**, because `DESIGN.md §4.1` forbids a `bug` plan with no red loop.
5. Path `deep`, or grilling hits a fact: read `references/research.md`, dispatch Explore subagents (`model: config.models.research`), write `research.md`, run `verify-citations.mjs`.
6. Read `references/plan.md` and `references/design.md`. Grill in rounds until the frontier is empty; every design field filled; decisions table complete; tasks are tracer bullets with acceptance criteria.
7. Path `deep`: dispatch `hodos-plan-reviewer` (`model: config.models.planReview`); fold its findings; at most one repeat.
8. Present the plan summary (goal, decisions, tasks); ask for approval. On approval: create the branch per `config.conventions.branch` (ask if it exists; a task upgraded out of `inert` keeps the branch it has); `ledger.mjs add "Plan: approved" --tasks <n> --branch <name>` (the script records `base` from `git rev-parse HEAD`, sets phase `approved`); print exactly `/clear` then `/hodos:run <slug>`.

**Invariants (first 40 lines of the kernel).** No code is written in S1, except by an `inert` verdict's own flow (decision **0183**). References are read on entering their phase, fail-closed. The router spends ≤5 evidence calls (decision 0029). Facts are fetched by subagents, decisions are asked of the human — the grilling agent never answers its own questions. Nothing is assumed silently: every open question has an answer or an owner before approval.
**Completion.** `state.phase == approved` and the handoff line printed. On an `inert` verdict: `Finish: report delivered` after one reviewer and no verifier, or an `Upgrade: inert→quick` line, with the edit reverted, back at step 6.
**Anti-pattern.** Starting to implement "since the plan is small"; a router that opens files to decide; a plan approved with open questions.
**Limits.** Kernel ≤150 lines; references per `AUTHORING.md §7`.
**Depends on.** `config.mjs`, `ledger.mjs`, `verify-citations.mjs`, `campaign`, `hodos-plan-reviewer`. For step 2i also `review-package.mjs`, `hodos-reviewer`, and `run`'s `references/review-loop.md` and `references/finish.md`.

#### `references/route.md`
Procedure: extract intent; classify type (`feature/bug/refactor/question/spike/upgrade`, the last two by the tests of `FORMATS.md §3`); fill the nine checklist rows with evidence (file estimate via Glob/Grep, new module, contracts, dependencies, migrations, more-than-one-mergeable-unit, fog, developers, waits); apply the verdict rules of `FORMATS.md §3`; propose with a one-line rationale per alternative. `bug` type adds: identify candidate red-loop commands (failing test, curl, CLI, browser) — the plan must open with one — and, after the verdict is printed, `ci.failedRun` for the report's branch or commit and `logs.trace` for the error it describes, each returning one more candidate and each `Skip: <role> unavailable` when its adapter is `null`. Completion: verdict and checklist written to `brief.md`, confirmed by the user. Anti-pattern: exploring instead of deciding.

#### `references/inert.md`
Procedure (decision **0183**): write the inert form of `plan.md` (`FORMATS.md §5`) from the short plan the verdict's question approved; create the branch and record `Plan: approved`; per task, `Task <n>: started`, the edit, `commands.test` and `commands.lint` once each into `evidence/`, one commit, and `Task <n>: done --sha <sha> --inert`; a red command re-run with the edit stashed (`git stash -u`) to tell a red tree from a behaviour change; `review-loop.md` §2–§7 as written, with `ACCEPT` going to `finish`; `finish.md` with the verify fields read as the commands' evidence. The ratchet: a line a program reads, whether the edit needs it, a command shows it, or the review names it, writes `Upgrade: inert→quick`. The ledger then restarts the task count and both loops (decision **0184**). Every commit since the plan's base is reverted, fix-pass commits included, the task returns to step 6 at phase `plan`, and the full plan's T1 rebuilds it test-first on the same branch. Completion: `Finish: report delivered` with no `hodos-verifier` dispatch, or the upgrade. Anti-pattern: classing a change `inert` to skip the verifier. Bound: the review loop's two iterations.

#### `references/reproduce.md`
Procedure: state the symptom as an observable (what is seen, where, what was expected instead), asking when the description carries fewer than three parts; pick the cheapest harness of the five-row table that can carry it — an existing test, a new test beside its neighbours, a command against a running service, the project's CLI, a browser recipe — and go no further down than the symptom requires; **three attempts, each one command**, each recorded in `brief.md` as `- attempt <k>: <what was run> → <what it printed>` and **never in the ledger**, because the `red-check attempt` form derives `phase: execute` and would report an unplanned task as being built. A test written to the current wrong value is green and proves nothing. Reading the implementation for a cause is out of scope — that is the phase after this one. Exit A: the `## Reproduction` block (`Command:`, `Red:`, `Harness:`), copied into `plan.md` as T1 verbatim. Exit B: `Ruling: not reproducible here — <what was tried> — <what would make it reproducible>`, the three attempts and the two ways forward said to the developer (get what is missing, or re-route to `question` or `spike`), and no plan written. Completion: `brief.md` carries a runnable `## Reproduction`, or the ledger carries the `Ruling:` and the developer has the choice in front of them; every attempt is in `brief.md` either way, with what it printed. Anti-pattern: fixing it; explaining it; a test written to the current behavior so that something is green; a fourth attempt because the third nearly worked. Bound: three attempts — the fourth is exit B.

#### `references/research.md`
Procedure: turn open facts into numbered questions; one Explore subagent per question (read-only), answer ≤1.5k tokens with `path:line` facts and a files-to-read list; precedents (≥2 places); external APIs with the installed version from the lockfile and the doc source for that version (`docs.getDocs` pinned; WebFetch/WebSearch is reconnaissance only); risks; a negative result requires a second search of a different shape. Write `research.md`; run `verify-citations.mjs`; failing citations are fixed before use. Completion: every question answered with citations or marked open for grilling. Anti-pattern: a subagent that answers the design question instead of the fact question.

#### `references/plan.md`
Procedure: grilling rounds (frontier → `AskUserQuestion`, four questions per call, the recommended answer first (decision **0178**) → wait → recompute); decisions table; blast radius per task from `codeIndex.blastRadius` on the symbols the task changes — `must_touch` into the task's `Files:`, `may_touch` there or into `## Non-goals` with the reason — `Skip: codeIndex unavailable` when `null` (decision **0091**); tasks as tracer bullets with files, acceptance before code, and the test strategy of `DESIGN.md §6.2` — test-first by default, written as no line at all, or one of the four exemptions with both halves (decision 0022); verify plan mapped to `config.verify.recipes`; refactor-in-scope list; non-goals; for `bug`, T1 is the red loop — supplied verbatim by `references/reproduce.md`'s exit A when the description named no failing command; for `upgrade`, T1 is the project's own commands **run and recorded** on the current version, so that what the bump breaks is separable from what was already broken; for `refactor`, the done-metric is a command with a number. A `spike` plan carries `## Question` (falsifiable), `## Timebox` (what happens at the bell) and `## Exit` (both outcomes, chosen now) **in place of `## Tasks`** and of acceptance criteria, with the ten design fields present as `none — <reason>` where they do not apply (decision **0084**). Prototype rule: one design question, labeled, deleted. Advisory: >250 lines → "check whether this is one mergeable unit". Completion: `Open questions` empty; user approved. Anti-pattern: a plan with "TBD"; a task whose acceptance criterion is "works"; an exemption reason invented outside the four.

#### `references/design.md`
The design-field table (`DESIGN.md §6.2`) with one line of guidance per field, the precedent-first rule, the wrapper rule, and the "design it twice" requirement: 2–3 real alternatives compared in the decisions table by one planner. External APIs: version from lockfile, source per version. One `design.getFrame` here, on plan, and none during execute — the frame's spacing, colors, variants and states become numbers in `### Interfaces` and `### Data & scale`, so execute pulls nothing — and `db.schema` for the tables the task touches, whose columns, nullability and indexes `### Data & scale` carries; each `Skip: <role> unavailable` when `null`, the schema falling back to the migration files it names. Target ≤120 lines.

### 1.2 `run` — S2 kernel

**Purpose.** Own session 2: execute the approved plan task by task, simplify, review loop, verify loop, finish. Resume from the ledger after any interruption.
**Invocation.** `/hodos:run <slug>`.
**Inputs.** `plan.md`, `ledger.md`, `state.json`, rules, code, config.
**Outputs.** Commits; `review.md`/`verify.md` (transient); `plan.md#Outcome`; the finish report.

**Procedure (standing).**
1. `config.mjs find`; read `state.json`; phase `done` → say the task is finished and stop; phase before `approved` → say which S1 step is missing and stop; otherwise `ledger.mjs claim <slug>`, which writes this session's pointer, or `active` where no session id is reachable (decisions 0047, **0171**). A kernel never writes machine state itself (`DESIGN.md §5.1`), and a session that stops claims nothing.
2. Resume by `state.phase` (`FORMATS.md §7`), and on an `inert` task in `skills/task/references/inert.md` at the section its phase names (decision **0183**): `approved`/`execute` → `references/execute.md` from `tasks.current`; `review` → `references/review-loop.md`; `fix` → fix per the open findings; `verify` → `references/verify-loop.md`; `finish` → `references/finish.md`; `manual` → tell the user the task is in manual mode and stop.
3. Phases run in order: `execute.md` (+ `defaults.md`) → `review-loop.md` → `verify-loop.md` (+ `oracles.md`) → `finish.md`.
4. Every fork the plan did not settle: if it changes behavior, contract, structure, or dependency → `AskUserQuestion` with options and a recommendation, then `ledger.mjs add "Gap: …"`, and where the answer contradicts an `Acceptance:` clause, that clause is rewritten in `plan.md` with the approved wording kept as `Amended <date> by Gap: …` (decision **0176**); otherwise decide and `ledger.mjs add "Ruling: …"`. Under `config.autonomy == "rulings"` the first case becomes a ruling too, except destructive/outward actions.

**Invariants (first 40 lines).** The plan is the contract; deviations go through the chat. Machine state only via `ledger.mjs`. A diff is judged by the reviewer and the verifier, and walked once by its author in the simplify pass; the kernel never reads one to review it. Subagents are dispatched with the `hodos-*` definitions, never as forks. Commit per task, no push, no merge. Loop bounds are 3 / 2 / 2.
**Completion.** `Finish: report delivered` in the ledger; report in chat.
**Anti-pattern.** Continuing after a red check "with a small workaround"; reviewing the diff inline "to save a dispatch"; declaring done without the verify table.
**Depends on.** `ledger.mjs`, `review-package.mjs`, `hodos-reviewer`, `hodos-verifier`, `campaigns.mjs`.

#### `references/execute.md`
Per task: `ledger.mjs add "Task n: started"` → write the acceptance check first and run it — it must be red — then `ledger.mjs add "Task n: test red"`; a task carrying one of the four exemptions (`visual`/`glue`/`infra`/`no-harness`) skips this and passes `--tests <reason>` on `done` instead (decision 0022) → implement, a comment or document carrying the fact itself and never a `.claude/hodos/tasks/` path (decision **0172**) → run the task's check (plus `config.commands.typecheck` when types changed) → red → `ledger.mjs add "Task n: red-check attempt k/3 — …"`; third failure → stop and diagnose in chat → green → mutation check on new tests (break the pinned line, red, restore) → `ledger.mjs add "Task n: mutation" --tests <k>`, `<k>` the number of tests this task wrote and mutated, `0` where it wrote none (decision 0122) → commit with the project convention → `ledger.mjs add "Task n: done" --sha <sha>`. After the last task: simplify pass over `git diff <base>..HEAD`, walking `defaults.md`'s ladder and stopping at the first rung that holds; one emitted line per cut and a closing `net: -<N> lines`; a cut declined because the simpler form is correct but bounded gets a `hodos:` marker in the code instead; commit, `ledger.mjs add "Simplify: done" --sha <sha> --net <n>`. Two shapes are not this loop. **`mechanical`** (the shape of `refactor`): the codemod is the artifact, the red phase applies to the codemod rather than to each file, and the review is packaged `--mechanical <codemod>` — the codemod plus a three-file sample, every other file named under `## Not packaged`. **`spike`** (the type): no red phase, no per-task commit, and no review or verify — work against the timebox, take the exit the plan named, and write one `Ruling:` naming the answer **and the exit**. Completion: every task `done` and `Simplify: done`, `state.phase` reading `review`; a spike satisfies none of the three and completes on §6b's terms instead — the exit taken and the `Ruling:` written. Anti-pattern: two tasks in one commit; a "temporary" `any`; `--tests` on a task the plan did not exempt; a spike that starts committing tasks.

#### `references/defaults.md`
The defaults list (`DESIGN.md §7.2`) as positive one-liners, ordered by the seven-rung ladder the pass stops at the first holding rung of, plus a four-row red-flags table for rationalization ("this case is simple" → "simple cases are where unexamined assumptions cost most"; "the rule doesn't fit here" → "a rule that doesn't fit is a `Gap:` for the chat, not a silent exception"; "I'll clean it up later" → "later is the simplify pass, and it runs now"; "the test is basically right" → "prove it with mutation"). Carries the two forms the pass writes: a cut line `L<line>: <tag> <what>. <replacement>.` over `delete/stdlib/native/yagni/shrink`, closing with `net: -<N> lines`; and the marker `hodos: <ceiling> — upgrade when <trigger>` for a cut declined because the simpler form is correct but bounded — both halves mandatory, never for unfinished work and never for a known defect (decisions 0017, 0018). Target ≤100 lines.

#### `references/review-loop.md`
`review-package.mjs <slug>` → dispatch `hodos-reviewer` (`model: config.models.review`) with the input path, the rules dir, the config path → wait for the completion notification → read `review.md` (verdict + findings only) → `ledger.mjs add "Review k: <verdict> b/m/mi"` → `ACCEPT` → done; otherwise fix blockers and majors (minors if cheap), commit, `ledger.mjs add "Fix k: done" --sha <sha>` → iteration 2: `review-package.mjs <slug> --since <fix-sha>`, dispatch again with the previous `review.md` → still not `ACCEPT` → `AskUserQuestion` breaker: accept with open findings / continue manually / roll back to task N → `ledger.mjs add "Breaker: review — <choice>"`. Never tell the reviewer what not to flag. Completion: `ACCEPT`, or a `Breaker:` line. Anti-pattern: a third iteration; pre-judging findings in the dispatch prompt.

#### `references/verify-loop.md`
`env.mjs up` before the dispatch and `env.mjs down` on every path out (decision 0074): a blocked layer is one `AskUserQuestion` offering to write the `permissions.allow` entries, whose decline degrades that layer's `browser` and `http` claims to a skip with the reason and leaves the command recipes running; a layer still red at its own timeout is one `hodos-preparer` dispatch, then `env.mjs probe` here, then §9's breaker if it is still red. No profile declared, and `commands.dev` is the environment, unchanged. Then dispatch `hodos-verifier` (`model: config.models.verify`) with the plan path, the recipe names whose `when` matches, the adapter path, the `oracles.md` path (decision **0106**), the evidence path → wait → read `verify.md` verdict → `ledger.mjs add "Verify k: <PASS|FAIL> n claims, s skipped"` → `FAIL` → fix **in severity order**, commit, `ledger.mjs add "Fix k: done" --sha <sha>`, re-dispatch (iteration 2 re-verifies the failed claims) → still `FAIL` → breaker, whose question names the counts by severity (decisions **0097**, **0108**). The files the `when` globs are matched against are the tasks' `Files:` lines **and** the call sites `review-input.md`'s `## Callers` names, which is decision **0094**'s regression surface: a change reaching the UI only through a caller still matches `ui`, so that recipe's routes are swept and its `checks[]` — the pins an earlier task left — are run. A row whose defect is outside this task's diff is not fixed here whatever its status; `finish` reports it (decisions **0120**, **0125**). Three of the four bounds of decisions **0096** and **0112** are set here rather than in the agent: the sweep's size is `matrix.mjs` over the recipe's routes × states × widths, covered pairwise; the recipes are the `when`-matched ones and no others, which is what keeps the surface the diff's; and the stage order — command recipes, then `http`, then the browser sweep — is what makes a red unit stage cost one skip per row instead of a browser sweep. The fourth — the attacks run only on the routes the diff resolves to — is the agent's to resolve, because resolving a file to a route means reading the project's route table and the imports around it, and the agent is what has them open. It reads the diff with the plan header's `Base:` sha rather than the plan's `Files:` lines, for the reason decision **0076** gives about projects: the plan says what a task meant to touch. Verify fixes are not re-reviewed; they are listed in the finish report. Completion: `PASS`, or a `Breaker:` line.

#### `references/oracles.md`
The catalogues the verify phase runs from, handed to the verifier **by path in the dispatch** the way `defaults.md` is handed to the reviewer (decision **0106**): the four sources an unclaimed row is admissible from — console or network on a visited route, a detector hit, a crash under an attack, a pin that no longer holds — and nothing else (decision **0093**); the five detectors of `scripts/detectors.mjs` with the four measured thresholds and what `verify.detectors.allow` silences (decisions **0107**, **0109**); the closed five-attack list with the operations that run it and the six conditions that say it passed; the stage order — command recipes, then `http`, then the browser sweep — with `skip: not run — <recipe> red` for a stage behind a red one, and `scripts/matrix.mjs` for the sweep's size; the shape of `## Not covered`, whose residue line is fixed text (decision **0096**); and **the statuses** — the five, decision **0108**'s six-row severity table, the `git worktree` run that earns `pre-existing` on a command row and the bounded `git` proof that earns it on a browser one (decisions **0097**, **0119**, **0127**), the single unexplained retry behind `flaky` (**0126**) and the median-and-p95 rule for a number (decision **0098**). An **enumerable status rule** — a table, a recipe, a retry count — is here; what a row's own status *is* stays the agent's, and the two things it does about one rather than reads (retry once, mark a row `pin`) are named there (decision **0116**). Target ≤175 lines, raised from 150 when 0116 landed the statuses: the enumerable half measured **51** lines against that decision's estimate of ~37.

#### `references/finish.md`
Fold `review.md` + `verify.md` into `plan.md#Outcome` (verdicts, open minors, evidence paths, gaps count), or on an `inert` task `review.md` alone, with the `Verify:` line naming the two commands' evidence (decision **0183**); copying `verify.md`'s `## Claim feedback` out before the deletion step and printing it in the report (decision **0092**); the `Verify:` line carrying the severities of its `fail` rows and the `flaky` and `pre-existing` counts, which is where a defect the run found and did not introduce survives the file (decisions **0097**, **0119**); the `pass · pin` rows copied out with the feedback and put to the developer in **one** `AskUserQuestion`, each accepted row appended as `{route, evaluate, expect}` to `checks[]` of the `browser` recipe in **the config that recipe was read from**, with `config.mjs check` run after the edit — an error reverts it and pins nothing, a warning names the predicate and which of the three forms it took — a class or an id, a walk rather than a query, a bare expression rather than a function (decisions **0118**, **0129**, **0130**) — and is reported (decision **0094**); delete the transient files; campaign node → `campaigns.mjs node-done <campaign> <node> --sha <sha>` and `campaigns.mjs measure <campaign>`; proposals only where a finding traces to a missing convention, with two `Grep` counts behind them — ≥2 precedents of the target → a rule proposal, 0–1 precedents with ≥2 of the flagged shape → a convention proposal the developer decides rather than confirms, neither → an observation line (decision 0050); an accepted proposal of either kind is written by invoking the `rule` skill (decision 0016), never by hand; hook proposal on a repeated rule violation; `verify-citations.mjs .claude/rules/*.md`, and each anchor that moved in a file the branch changed re-pointed on one `AskUserQuestion`, the edit left for the developer's `docs(rules)` commit before the merge and named in the report (decision **0180**); `tracker.link` once on the id the branch name or the brief's ticket key carries, which is outward-facing and therefore a mandatory stop under every autonomy setting (`DESIGN.md §4.4`) — declined, `null`, or no id → `Skip: tracker unavailable`, and the report carries a `Tracker:` line either way; `ledger.mjs add "Finish: report delivered"` (the script appends the history line and removes every pointer naming the task, `active` included); report to chat: done / gaps / rulings / open minors / proposals / "delete `tasks/<slug>`?" → on yes, delete the directory. At most **one** offer line, on the same script-decidable preconditions and the same priority as the digest's (`FORMATS.md §12`), computed after the re-point so that an anchor just re-pointed is not offered as rot, silent by default — a silent run produces nothing and the report does not mention it. A `spike` arrives here from `approved` with no review and no verify to have passed: `## Outcome` and the `Ruling:` both name which exit was taken, the branch is the developer's to delete, and nothing merges. Completion: report delivered, node updated. Anti-pattern: a rule proposal from a single incident; "Great, all done!" before the table; a pin written without the question, or from a row that does not carry its own value.

### 1.3 `init`

**Purpose.** Learn the project once; write the project layer with approval.
**Invocation.** `/hodos:init` · `/hodos:init --refresh`.
**Inputs.** The repository; existing AI instructions; `.mcp.json`; the developer.
**Outputs.** `CLAUDE.md` map or managed block; `.claude/rules/*.md`; `.claude/hodos/config.json`; `.gitignore` entries; `permissions.allow` for hodos scripts in `.claude/settings.local.json` (on approval); approved hooks in `.claude/settings.json`; the migration ledger applied.

**Procedure.** Steps 0–8 of `DESIGN.md §8`, each in its reference:
- `references/scan.md` — inventory checklist; area briefs for Explore subagents (`model: config.models.initScan` or `sonnet` before a config exists): stack & commands from scripts/Makefile/csproj/CI; architecture from folder layout, import direction, DI; conventions from 5–10 representative files per area hunting Unusual/Opinionated/Tribal/Consistent with ≥2 precedents; tests: framework, structure, mocking, what is asserted; existing-instructions inventory; nested project detection; commit-convention detection from `git log`; and one inventory line for **where the application declares its routes**, `absent` where it serves none — the fact the attack surface (decision **0112**) and `--refresh`'s pin prune (decision **0094**) both call a "route table" and had nowhere to find.
- `references/interview.md` — recall questions in batches ≤8; the standing questions (what Claude gets wrong here; why this pattern, not the default; exceptions; how to run for verify — ports, auth, test data; what not to touch; tracker/branch/commit; language); never ask what the scan answered; when the repo contradicts the developer, show the evidence and ask.
- `references/rules.md` — the three sources, the three-question filter, the rule form (`AUTHORING.md §10`), sources fetching (`sources/<stack>.md` → `docs.getDocs`/WebFetch → candidates), the report-before-write table (rule, paths, precedent, source, justification, the `keep`/`target` judgement and what carries it, form).
- `references/config.md` — the field list the write step reads instead of the specification (decision **0066**): the four fields `init` computes and where each value comes from, then every key with what it admits, ≤60 lines, derived from `FORMATS.md §2` and citing it.
- `references/migrate.md` — the ledger for existing instructions: one entry per instruction, `retain / rewrite / relocate / automate / delete`, evidence, what is lost, approval flag; a relocation target must itself be loaded or behind an observable trigger; nothing lives in two loaded files.
Write phase: managed block `<!-- hodos:begin -->…<!-- hodos:end -->` in an existing `CLAUDE.md`, a new ≤60-line map otherwise; rules with `paths:` and anchored precedents; config from `references/config.md` with commands **run once** and `verifiedAt`/`scanSha` recorded; `.gitignore`; `permissions.allow: ["Bash(node <plugin root>/scripts/*)"]` in `.claude/settings.local.json`, the plugin root resolved from `${CLAUDE_PLUGIN_ROOT}` in the skill body rather than written literally (decision 0057); hooks only if approved, and into the committed `.claude/settings.json`. Self-check: `config.mjs check`, then `lint.mjs --project`.
`--refresh`: `git log --diff-filter=DR --name-only <scanSha>..HEAD`; precedents that have rotted — a citation that no longer resolves, an anchor whose text has moved, a bare path that is gone (decision **0078**), the last two through `lint.mjs --project`; drift counts; **pins whose route is gone**, one prune proposal each naming the route, the predicate and nothing else — a pin whose route still resolves is left alone, because whether it holds is the verify phase's answer and a check removed here is a regression nobody will notice (decision **0094**), and a predicate `config.mjs check` warns about — a class or an id, a walk rather than a query, a bare expression rather than a function — is a re-point proposal beside them (decisions **0118**, **0129**, **0130**); new areas; a delta report before write.
**Completion.** Config verified by running its commands; lint green; every write approved.
**Anti-pattern.** Rules that restate what the model knows; asking the developer to confirm a path-checked fact; rewriting an existing `CLAUDE.md`.
**Limits.** Kernel ≤150; ≤8 questions per batch.

### 1.4 `campaign`

**Purpose.** Create or advance a campaign map.
**Invocation.** `/hodos:campaign <idea>` · `/hodos:campaign <slug>` (advance). On a campaign verdict, `task` invokes this skill through the Skill tool (decision 0016).
**Procedure** (`references/map.md`): campaign-level grilling (goal; done-metrics as commands with expected numbers, measured now via `campaigns.mjs measure`; architecture direction D1..Dn; decomposition — tracer bullets or expand–contract; fog list; waits); write the map (`FORMATS.md §11`); `campaigns.mjs frontier <slug>`; propose one node; on confirmation invoke the `task` skill as `<slug>/<node>` and `campaigns.mjs claim <slug> <node> <owner> <branch>`. Advance mode: re-measure, show frontier/blocked/fog/waits; empty frontier → name the wait and propose nudge / pull from fog / drop. Decision and research nodes resolve in-session and append a `D` row. Changing a campaign decision happens here, never inside a node.
**Completion.** Map written; one node proposed or started; metrics current.
**Anti-pattern.** Cutting fog into nodes; a map that retells a task's plan; resolving two nodes in one session.
**Depends on.** `campaigns.mjs`, `task`.

### 1.5 `status`

**Purpose.** Show state and hygiene.
**Procedure.** `state-digest.mjs --full --fetch` — the `--fetch` half is the one network call the engine makes (decisions **0080**, **0138**): `git fetch --no-tags --quiet` under five seconds in each repository a map lives in, refs only, failing open to `fetch failed — the map is as of your last pull` and the local map; no hook passes the flag; `config.mjs check`; `lint.mjs --project`; `ledger.mjs sessions` (`--gc` on confirmation); `campaigns.mjs find` + `frontier` for each map, which from Stage 9a `state-digest.mjs --full` carries in-process — one Node start on that budget, not two. Shows: active tasks with phase and last event; stale tasks (`ledger.md` mtime older than `staleDays`) with "fold or delete" prompts; campaigns: frontier, blocked, fog, waits, claims seen on branches; upgrade rate from `history.jsonl` (tasks with `upgrades > 0` / tasks finished in the last 30 days), the override rate (`overrode`) and the last five `gapTexts` beside it (decision 0046) — under three finished tasks in the window the counts print and the percentages are withheld with the reason (decision 0051); `--cost` as its own run, printing each task's token counts from `usage` and their totals, and no dollar figure (decision 0045); lint results (rules whose `file:line` precedents no longer resolve or whose anchors have moved, bare paths that are gone, over-cap files, frontmatter warnings). Offers actions; performs deletions only on confirmation.
`--debt` is a separate read-only run: grep the project for `hodos:` markers (skipping `node_modules`, `.git`, build output), one row per marker grouped by file — `<file>:<line>, <what was simplified>. ceiling: <the limit>. upgrade: <the trigger>.` — tagging any marker that names no trigger `no-trigger`, closing with `<N> markers, <M> with no trigger.` or `No hodos: debt.` It changes nothing (decision 0017).
`--prune` is a third run of its own, over `references/prune.md`: `lint.mjs --rules` prints the four facts decision **0082** names — each rule's age (first arrival, followed through renames, or `age unknown — not committed`), its size in lines, its precedents and which of them have rotted — a citation that no longer resolves, or an anchor whose text has moved (decision **0078**) — plus the layer's token cost — and one `AskUserQuestion` per rotted rule offers keep · re-point · delete. It calls no rule dead — nothing measures that (decision **0082**) — and it is the only place this skill deletes a file the developer wrote.
**Completion.** Digest printed; every stale item has a proposed action; `--debt` prints the ledger and its count; `--prune` asks only about rules whose citations have rotted.

### 1.6 `rule`, `skill` and `adapter`

`rule` is model-invocable: the finish phase invokes it for an accepted rule proposal (decision 0016). It writes one project rule by `AUTHORING.md §10` — grep for precedents first, run the three-question test aloud with evidence, draft, confirm, write to `.claude/rules/<name>.md` with `paths:`, `lint.mjs --project`. Refuses to write a rule that fails question 2.
`skill`: write one project-specific skill (a procedure the project needs and hodos does not ship — e.g. "regenerate the API client") by `AUTHORING.md §11`; register it in the CLAUDE.md map.
`adapter`: write one project adapter into `.claude/hodos/adapters/<role>/<tool>.md` and set its config entry to `project:<tool>` (decision 0062). Three questions, the first of which refuses: is the server in `.mcp.json` or merely live in this session · does one of the eight roles call it · what does the schema not say. Every tool id comes from a live schema. All three are small skills (`AUTHORING.md §7`).

### 1.6a `review` and `handoff`

Both are small skills, both `disable-model-invocation: true`, added by decision **0081** where the entry is not a task at all. The model-invocable set stays at three.

`review`: `/hodos:review [branch|ref|a..b|path]`, defaulting to the current branch. `review-package.mjs --target <t>` writes the package to a temporary directory; one `hodos-reviewer` is dispatched against it with `config.models.review`; the verdict, the blockers and majors, the reviewer's Coverage line and the path to `review.md` are printed. Tracked, uncommitted; the developer commits it, and `/hodos:run <slug>` on another machine offers the pickup and deletes the file (decision **0083**). It writes no ledger line and does not touch the task directory. Completion: the file exists, `git status` shows it as the one new file, and the developer knows what to commit and push.

## 2. Agents

**Dispatch semantics (all agents).** The kernel dispatches with the Agent tool naming the definition as `subagent_type: "hodos:<agent>"` — the plugin-qualified form, verified 2026-09-01 (`PLATFORM-NOTES.md` fact 33); the bare name is rejected with the list of available agents, and is an error rather than a fallback. `model` is passed per dispatch from `config.models.<role>`, which the Agent tool honours (fact 34). The per-dispatch turn bound is **not** passed: `maxTurns` is a field of the definition itself (facts 36 and 40, decision 0044) — a machine bound on an agent, where the 3 / 2 / 2 of `DESIGN.md §4.5` bound only the kernel. An agent that reaches its bound returns **nothing** — no verdict line — so the kernel stops with that diagnosis instead of recording a verdict, and never resumes it. The verifier is the one agent that may have left its output file behind anyway: it writes `verify.md` before the attacks (decision **0112**), so the stop names the file where it exists. That changes what the developer can read, not what the kernel records — a partial table is not a verdict. Dispatch runs in the background: the kernel does not poll or sleep — it waits for the completion notification, then reads the agent's output *file* (`review.md`, `verify.md`), never its transcript. The dispatch message contains paths and one-line instructions only — no pasted plan, no pasted diff, no conversation history. Agents write exactly one output file (plus `evidence/` for the verifier) and return exactly one verdict line. Agents do not dispatch agents.

### 2.1 `hodos-reviewer`

`model: opus` (overridden per dispatch by `config.models.review`) · `tools: Read, Grep, Glob, Bash, Write` · the prompt restricts `Write` to `review.md` and forbids any change to the tree, index, HEAD, or branches.
**Inputs.** Path to `review-input.md` — whose header carries the `Mutation:` counts, the one route decision **0122**'s number has into this closed list (decision **0143**); the rules directory; `config.json` (for commands); for iteration 2 the package's `## Previous findings` — the previous `review.md`'s Spec section and Standards table, verbatim (decision **0175**); on an `inert` task, the package's `## Shape: inert` section in place of `## Design` (decision **0183**).
**Procedure.** Run `config.commands.test`, `typecheck`, `lint` verbatim (`null` → `check: not configured`); record results — once per project the package's `## Projects` names, wherever it carries that section, each in its own directory and each of those rows suffixed ` · project: <dir>` (decision 0076). Read the input file. Spec section: Missing / Extra / Misunderstood against the plan's goal and tasks, plus **Unclaimed** — a typed state's member, a branch's failure path or a clause of `### Invariants & failure modes` that no `Acceptance:` clause of the package names, on every path, with no severity and no effect on the verdict (decision **0092**); a task's `Tests:` exemption whose stated reason does not hold on the diff — a branch under `glue`, logic under `visual` — is a `major` (decision 0022); in an `inert` package, an edited line a program reads is a `major` with `Item: shape`, whose fix is the upgrade and never an edit (decision **0183**); the package's `Mutation:` header compared against the test declarations the diff adds per task, a disagreement being a `major` and `—` on a diff that adds declarations being the record missing, while `— (ledger.md unreadable)` is a Coverage line (decisions **0122**, **0143**). Standards section, two passes. Convention pass: findings against project rules, the plan's design fields (dependency direction, data assumptions, refactor-in-scope both ways), the defaults list. Behavioral pass: the nine-row risk checklist carried in the prompt (`L1` shadow override · `L2` type-contract breach · `L3` boundary blindspot · `L4` state-mutation hazard · `L5` control-flow escape · `L6` callee-contract mismatch · `L7` concurrency/async · `L8` resource lifecycle · `L9` time/locale) run over the diff — the axis `defaults.md` does not cover, because it names what a model writes by default, not what it fails to see (decision 0015). Each finding = severity + `file:line` + item + one-line fix; a behavioral finding at `blocker` or `major` also carries a trigger, the concrete input or state under which it manifests. Confidence pass: drop any finding you cannot ground in a specific line and item, and any behavioral finding at those severities whose trigger you cannot name. Coverage: name what you did not review. Write `review.md`; return only the verdict line.
**Standing facts in the prompt.** The code was written by another agent. The implementer's report is testimony; a rationale never lowers severity. Inspect outside the diff only for one named risk with one focused check; unverifiable → a "cannot verify from diff" item for the orchestrator. Do not dispatch subagents. Skip anything the tooling already enforces. Praise is one line, at the top, only where earned.
**Completion.** `review.md` valid per `FORMATS.md §9`; verdict returned.
**Anti-pattern.** Findings without a location; "would look cleaner"; re-ranking Spec against Standards; crawling the codebase.
**Limits.** Prompt ≤150 lines; ≤400 words per section.

### 2.2 `hodos-verifier`

`model: sonnet` (overridden by `config.models.verify`) · no `tools` allowlist (inherits the session's tools including the browser adapter's MCP tools) · `disallowedTools: Edit, NotebookEdit` · the prompt restricts `Write` to `verify.md` and `evidence/`. A background subagent keeps every MCP tool (`PLATFORM-NOTES.md` fact 13, confirmed live by fact 41: a dispatched verifier answered with all 29 `mcp__chrome-devtools__*` names), so the verifier drives the browser from the background and there is no foreground path.
**Inputs.** Plan path (acceptance criteria + verify plan), beside which `ledger.md` holds the `Task <n>: mutation (<k> tests)` rows the mutation row's Evidence cell names its sample against (decision **0143**); recipe names; adapter file path; the `skills/run/references/oracles.md` path, which carries the four admissible sources, the detectors, the closed attack list, the stage order and the statuses (decisions **0106**, **0116**), and whose absence at the named path leaves the plan's claims running and is said in `## Not covered`; `evidence/` path; the profile the kernel raised, where the project declares one, which the verifier writes into `verify.md`'s first line (`FORMATS.md §10`, decision 0074). One config path and one recipe-name list per project the diff touches — the projects `review-input.md`'s `## Projects` already names, computed by `config.mjs for-files` over the diff and not predicted from the plan's `Files:` lines (decision 0076); where it names any, each row that reports a command that ran or an action that was taken carries ` · project: <dir>` in its command cell, and a row copied forward from an earlier iteration keeps the one it had (`FORMATS.md §10`).
**Procedure.** For every claim in the plan's tasks and verify plan: choose the recipe; run the command or drive the browser via the adapter (navigate → snapshot → act → screenshot to `evidence/<nn>-<name>.png`, console and network checked for errors; an `a11y` recipe audits the route and reports by `impact`, a `viewport` recipe re-visits it at each declared width — decision 0095); record claim → command → evidence → status, the Status cell being the status and then at most one word — `fail · <severity>` from decision **0108**'s table, `pass · pin` on a `browser` row whose predicate is worth keeping (decision **0094**). A `browser` recipe also runs every `checks[]` predicate it declares, and one that no longer returns its `expect` is a row with source *pin*. A failing browser or command row is retried **once**: a pass on that retry is `flaky` where nothing explains the failure, both outputs in evidence, and it fails the verdict (decisions **0098**, **0126**) — a failure whose mechanism the verifier can name is a `fail` at its severity instead. A failing **command** row is re-run in a `git worktree` at the plan header's `Base:` sha — red there too and it is `pre-existing` with both outputs, green there and the change broke it, no base run at all and it stays a plain `fail`; a **browser** row has no base **run**, and can still have a base **proof** from `git` inside `FORMATS.md §10`'s bound — the elements byte-identical at base and the diff touching nothing their render depends on; outside the bound the row is `fail · major` and its evidence says so (decisions **0097**, **0119**, **0127**). A claim whose evidence is a number names its statistic, and a timing claim reports median and p95 over ≥5 runs (decision **0098**). Sample ≥1 new test for mutation (break the pinned line, run, red, restore), the row's Evidence cell ending ` · 1 of <k> new tests` from the ledger, or ` · 1 of an unrecorded count` where it holds none (decision **0122**), or — where the rows sum to 0 and the diff adds no test — ` · 1 of 0 new tests — mutated <file>:<line>, a line this diff changed`, on a test line the diff changed (decision **0173**). `perf` recipes only if the plan declared them. Add a row from the four sources of decision **0093** and no fifth — a console error or failed request on a visited route, a detector hit, a crash under an attack, a pin that no longer holds — the source named in the Command cell, an allowlisted detector hit counted in the route's evidence instead (decision **0107**). Every skip has a reason, a stage behind a red one writing `skip: not run — <recipe> red` and a route the diff does not reach writing `skip: not attacked — the diff does not reach this route` (decision **0112**); a claim missing from the table is a failure. Write `verify.md` before the attacks and rewrite it with their rows after (decision **0112**), with `## Claim feedback` after the table — unfalsifiable, redundant and absent claims, three lines, `—` where there is nothing (decision **0092**); return the verdict line.
**Standing facts.** No claim without a command run in this message. Browser is for CSS/layout/cascade/animation/hover/breakpoints; a logic bug found in the browser becomes a finding "+ cover with a test". Never mock away the thing under test to make it pass.
**Completion.** Table complete and its header counts equal the rows — added rows included, all five statuses written — which `## Claim feedback` sitting outside the table leaves unchanged; every `fail` carrying the severity its source gives it; the three feedback lines and `## Not covered`'s three written, its residue line verbatim; verdict returned.
**Anti-pattern.** "Tests pass" without output; screenshots without a claim; a route dropped from the table; a row that says the code looks wrong, when the four sources are each something that ran; a severity chosen because the defect looked bad, when the table is what assigns it; a `pre-existing` with no base output behind it.

### 2.3 `hodos-plan-reviewer`

`model: opus` (overridden by `config.models.planReview`) · `tools: Read, Grep, Glob, Write` (writes `tasks/<slug>/plan-review.md` only) · `deep` path only.
Reads the plan, the research, the rules. Reports gaps that would cause real problems in implementation: missing design fields, ambiguous acceptance criteria, contradictions with rules or precedents, unstated assumptions about data/scale, decisions without a real alternative, a `spike` plan's numeric bar with no statistic to read it on (decision **0088**) and an acceptance clause that compares a number with no tolerance (decision **0177**), and a claim the plan's own contract demands that no clause names — a union member, a branch's failure path, or a clause of `### Invariants & failure modes` (decision **0092**). Approve unless there are serious gaps. Output ≤300 words; no rewriting of the plan. The kernel deletes `plan-review.md` after folding.

### 2.4 `hodos-preparer`

`model: sonnet` (overridden by `config.models.preparer`) · `maxTurns: 25` · `tools: Read, Grep, Glob, Bash, Write` (writes `tasks/<slug>/env.md` only) · dispatched by the **run kernel** before the verifier and never by it, because an agent that raises the environment and then grades what runs in it has an interest in the result (decision 0074).
**Inputs.** The layer's name, the directory its commands run in and the check that is still red; the config path; the layer's log under `.claude/hodos/env/`; the output path.
**Procedure.** Read the log and the failing check; re-run that check by hand — green now means the layer's `timeout` is too low for this machine, which is itself the finding; name one cause; fix and re-raise where the cause is the environment's; write `env.md` per `FORMATS.md §17`; return `raised` or `still red` with the cause in one clause.
**Standing facts.** One layer, the one the dispatch names. The project's source, tests and config are not what is broken. A cause it cannot fix from here — a credential, a machine grant, a service someone else owns — is a complete answer with what would close it. Do not dispatch subagents. Do not run the task's claims.
**Completion.** `env.md` written and the verdict line returned; the kernel re-probes the layer itself.
**Anti-pattern.** Editing the project to make a check pass; raising a layer it was not given; "should work now" with no re-run behind it.
**Limits.** Prompt ≤150 lines; one dispatch per entry into `verify-loop.md §3`.

## 7. Bench — `bench/`

The directory is named `bench/`, not `evals/`, to stay clear of the platform's own `claude plugin eval` layout (`PLATFORM-NOTES.md` check K).

Every bench metric is labeled **gate** or **measurement**. A gate carries a threshold and a failing run fails the stage; a measurement is recorded and read, never thresholded. The split exists so a number that looks good cannot stand in for a behavior that broke — the canonical case is a shorter diff that no longer runs (decision 0019). `router/`, `review/` and `noop/` scores are gates; sizes, token counts and costs are measurements.

- `fixtures/webapp/` — React + TS + Vite front end (3 routes, TanStack Query, a zustand store, vitest, eslint); `fixtures/api/` — Node HTTP API with tests; `fixtures/mono/` — a root `package.json` with two workspaces `web/` and `svc/` (monorepo fixture for nested configs and root-map lookup); `fixtures/kit/` — a tiny component library used as the "second repository" for external campaign maps. Each has 3–4 deliberate conventions (`http` client wrapper, error shape, module layout) documented in `fixtures/README.md` with `file:line`; committed with `package.json` + lockfile, `node_modules` ignored, CI runs `npm ci` in each. Fixtures ship **without** `.claude/`; Stage 3 produces one for `webapp` and commits it so later stages have a config.
- `scripts/fixture-copy.mjs <name> [--strip-claude]` — copies a fixture to a temp directory, runs `git init`, seeds three conventional commits so `git log`, `scanSha`, and commit-convention detection have a source, and prints the path. Every stage test that runs hodos against a fixture uses this copy, never the checked-in tree.
- `scripts/pair-seed.mjs` — the two-repository workspace of Stage 9b: `mono` as the home repository and `kit` as the external one, sibling checkouts under one workspace with a bare clone of each as its `origin`, the `badge-rollout` map committed in `mono` by a teammate, and that teammate's claim on a branch **only the origin holds** — the three properties decision **0040** refused `kit` for, seeded rather than dropped (decision **0077**). Names are fixed because a `repo:` name resolves to the repository root's directory name (decision **0134**). A seed, not a bench: it scores nothing.
- `router/set.json` — 35 task descriptions, each labeled with the expected path (`quick` · `standard` · `deep` · `campaign`), type, and campaign flag, and carrying the nine checklist rows of `FORMATS.md §3` that produce that path, so a label is derived rather than chosen (decision 0025); `router/run.mjs` scores accuracy and re-derives every label from its rows; `router/invoke.mjs` drives the scored run — a fixture copy per case, the invocation arm, the printed verdict and the tool-call count parsed out of it — and writes the verdicts file (decision 0027); `router/README.md` states which invocation path is used (check D). Thresholds: path ≥85%, type ≥90%, campaign flag ≥90% — gated at Stage 11, which owns the bench; Stage 4 records one run as a measurement, because a full run costs a quarter of a day's usage and a gate nobody can re-measure after a fix is not one (decision 0028).
- `run/plans/<name>.md` — approved plans the `run` kernel is exercised against, each shaped for one behavior (a `visual` exemption beside a test-first task, a correct-but-bounded form, a diff with nothing to cut, an acceptance check that cannot pass); `run/seed.mjs <plan> [--fixture <name>] [--copy <path>] [--into <dir>] [--gap] [--autonomy ask|rulings] [--at approved|review|verify|finish] [--setup <id>] [--defect <id>] [--rule-arm one|two] [--campaign <slug>/<node>]` turns a `fixture-copy.mjs` copy into a task directory — writes `plan.md`, runs `ledger.mjs init` and `ledger.mjs add "Plan: approved"`, creates the branch — and prints the copy's path; `--at review` continues past that point: it commits each task's implementation from `plans/<name>.impl/` and, with `--defect`, one seeded patch inside the task commit it names, running `ledger.mjs` for every event so the copy arrives at `phase: review` through the same script that would have written it live (decision 0036); a task the plan exempted records the exemption on its `done` line instead of a red run it never had (decision 0022), `--at verify` adds the `Review 1: ACCEPT 0/0/0` a clean implementation earns (decision 0043); and `--at finish` installs `plans/<name>.finish/{review-<arm>,verify}.md` and its `evidence/` into the task directory, then writes the gap, the ruling and the passing verify a run would have left, with the ledger's counts read out of the artifacts rather than written twice — `--rule-arm` picks which review is installed, one naming a pattern the code carries twice and one a pattern it carries once, which is the pair the ≥2-occurrences rule of `DESIGN.md §7.5` is tested against (decision 0048); `--campaign <slug>/<node>` fills the plan header's `Campaign:` field and passes the node to `ledger.mjs init`, which is how a task in one repository is seeded against a map in another (Stage 9b); `run/README.md` names each plan and the criterion it serves. A **harness, not a bench**: it produces inputs and scores nothing, so it carries neither gate nor measurement (decision 0033). Stages 6, 7 and 8 seed their own inputs with it.
- `review/seeded/<id>.patch` — ≥18 patches applying one seeded defect each to a fixture copy, each carrying its own metadata (fixture, kind, item, line, and the trigger for a behavioral one), ≥12 of them convention defects tagged by defaults-list entry or fixture rule and ≥6 behavioral across distinct `L` codes (decision 0015), plus `review/clean.json` listing 6 files that must produce no finding — except on the lines a seeded patch of the same package also changed, where the clean claim does not hold and a finding is the catch rather than a false positive. The patches are grouped into review packages of three or four so the reviewer sees a task-shaped diff rather than one defect, which is both the realistic input and the affordable one (decision 0037). A third kind, `spec`, is scored on the reviewer's Spec section rather than on a Standards row — a derivation gap the **Unclaimed** word answers (decisions **0092**, **0096**) — and carries `names`, the tokens that text has to contain. A fourth, `test-floor`, is the one defect in the set no sentence of the reviewer's prompt named when it first ran (decision **0121**): a diff that deletes an assertion and leaves the suite green. Thresholds, gated here: recall ≥80% overall and ≥80% for the `convention` and `behavioral` kinds, precision ≥85%. `recall, spec` and `recall, test-floor` are **measurements** and stay ones (decisions **0117**, **0121**): two seeded defects cannot carry a bar where one miss reads as 50%, and one cannot carry a bar at all. Neither kind is in the gated denominators, and the Spec section's own precision is measured by nothing, which is decision 0015's admission carried to Stage 12.
- `holdout/` — the reviewer's **hold-out set** (decision **0154**), kept apart from `review/` so that no case of it can enter a gated denominator. It has two sources:
  - `hyhmrright/logic-lens`'s 36 `logic-review` cases (MIT) — 30 defects as `seeded/` patches over `fixtures/snippets`, and 6 correct files as `clean/`, which are its *plausible but correct* half;

  `holdout/invoke.mjs` builds both kinds on `review/invoke.mjs`'s `prepare` and `runPackages`, and skips the pilot's when no checkout or cache is there. A pilot result is committed only as `redactPilot` keeps it (`file:line`, the item without its quotes, the verdict), and the rest goes to `pilot-cache/`. `holdout/run.mjs` scores them with `review/run.mjs`'s `score`: recall per source, L-code agreement, and false positives on correct code. Several runs given together are scored as one set, and a package reviewed in two of them is refused. Every number is a **measurement**, and `--check-key` holds the set to its own contract and not to the review bench's minimums.
- `report.mjs` — where a metric is labeled `gate` or `measurement`, for all three scorers' `--json`. It refuses the two ways a label drifts: a gate built without a threshold, and a measurement built with one (decision 0019). `measurementReport` is the hold-out set's report, and it refuses the third drift: any gate inside a set that is measured and never thresholded (decision **0154**).
- `noop/scenarios.json` — each scenario: the rule under test as `lines`, **every** file and line that states it, a fixture task prompt, and the behavior the rule is supposed to change, stated as a checkable direction. A rule has more than one home because the plugin ships its own specification beside the skills that restate it, and a control that removes one line removes no rule (decision 0073); a home embedded in a line carrying other rules names a `replaceWith`, the same line with the rule's clause taken out. `--check-scenarios` holds each named line to appearing in its file **exactly once** — a line written twice would take two behaviors with it — refuses a `replaceWith` equal to its line, and holds each check to one of six kinds (`transcript`, `transcript-absent`, `file`, `rows`, `metric`, `path-absent`), which is what keeps a scenario checkable from what the run left behind rather than from a reading. `noop/run.mjs` runs the prompt in two arms, with the line and with it removed, and a scenario passes only when the arms differ in the declared direction: the without-line arm is the control and is *expected to fail* the check — that delta is the whole signal, and without it "the behavior differed" is the reader's judgement rather than a result. Gate, with its threshold set from the first run that can produce one. Stage 11a bought two and neither could: run 1's control kept the rule, and run 2's — which removes every prose home of it — read 0 of 6 because the checked behavior happens in both arms, the arms differing only in turns, which decision 0019 forbids gating (decision 0073). The threshold stays unset rather than invented, and `--check-scenarios` carries a `probe` per scenario that reads the control copy for a surviving statement of the rule, so an unmeasurable scenario is found before a session is bought. The output is also the evidence for the PR policy in `AUTHORING.md §13`.
