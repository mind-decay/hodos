The pilot's own record. `BENCH.md` measures the engine against fixtures it authored; this file measures it against a repository it has never seen, on work the project wanted anyway. Every number here is labeled the way `BENCH.md` labels one — a **gate** carries a threshold and a failing run fails the stage, a **measurement** is recorded and read — and every measurement carries the sentence about what it does not prove.

Written at Stage 12c-1 (2026-09-09) before any task ran. The per-task numbers arrived at 12c-2 (§7). The measurements and the reading arrived after them (§9–§12). The `inert` shape's price arrived at 12d-2 (§13).

## 2. The arms, and the protocol that keeps them comparable

Two arms, ten tasks each: **hodos** (`/hodos:task` → `/hodos:run`, the plugin loaded with `--plugin-dir`) and **bare** (plain `claude`, no `--plugin-dir`, no hodos hook, no digest, the way this project was worked before 12b). Both arms run in the same repository, one task at a time, each on its own `feat/{slug}` branch off `hodos-pilot` — the pilot's integration branch, which is where every commit of this pilot has landed; `main` is seven commits behind it and is the rev the extracted crate's manifest pins (§5) — merged before the next begins.

Fixed before the first run, because a protocol written afterwards is a protocol fitted to the numbers:

1. **The arms alternate** — bare, hodos, bare, hodos — so whatever the developer learns about the family in run *k* is spread across both arms rather than banked in one.
2. **What the arms share is measured and disclosed, not claimed away.** Two things are shared by construction and cannot be designed out: every MCP task edits the one module that holds the wire types, `crates/ariadne-mcp/src/types.rs`, and every capture task threads `crates/ariadne-parser/src/adapters/treesitter/facts.rs`. Neither carries task-specific logic — each task adds its own field or its own arm of a match — so what a later task inherits is a file already open, not work already done.

   Beyond those, **one** share crosses the arms: the wrapper grammars inject TypeScript and Tsx (`adapters/treesitter/injection.rs:62-75` routes `Lang::Vue | Lang::Svelte` and `Lang::Astro` to their injection plans, `:94-99` resolves the injected layer to `Tsx`, `TypeScript` or `JavaScript`), so S1-bare's `astro.scm`/`vue.scm` reach captures S1-hodos's task writes. That pair is therefore run **hodos first**, against the alternation of item 1, so the arm that inherits is the bare one. The direction matters and the first two versions of this file had it backwards: T-1's multiplier is hodos ÷ bare, so a shared cost paid by the **bare** task raises the denominator and lowers the numerator and *flatters* hodos. Every unavoidable share in this pilot is ordered so **hodos pays first**, which is the conservative direction, and any pair where that is impossible is reported with the direction named. Two shares the earlier versions listed are not shares at all: `doc_for` builds `DocScope::default()` (`tools/doc_for.rs:53`) rather than a struct literal, so a new field on that type costs it nothing, and `crates/ariadne-mcp/tests/tools_read_symbol.rs` was both a bare task's test file and a hodos task's whole task — the assertion pairs were re-picked to exclude every file another task touches.

   **What the first pair realised.** The share this item anticipated arrived by a route it did not: pair 1's bare session read the hodos half's `plan.md` directly, at its seventeenth tool call of eighty-nine and before its first edit, and also read `.claude/hodos/config.json`. Nothing told it to. The hodos half had merged four `[src: .claude/hodos/tasks/api-surface-diff-caps/plan.md …]` citations into shared code — `crates/ariadne-graph/src/economy.rs:421`, `crates/ariadne-cli/src/commands/api_diff.rs:25`, `crates/ariadne-cli/tests/api_diff.rs:8`, `crates/ariadne-mcp/tests/tools_api_surface_diff.rs:8` — and the first sits on the very function the bare task had to extend. `.claude/hodos/tasks/` is gitignored, so it survives every checkout and no branch point hides it. Decision **0157** records this as an inherited share rather than voiding the run, on this item's own direction test: the bare arm got cheaper, so the denominator shrank and the multiplier rose **against** hodos. The mechanism is proposal **NNNN**, open for Stage 12d — an engine that writes citations into shared code while gitignoring what they point at. Every later pair inherits by the same route, and each says so in its row.

   **And the direction test alone was not enough.** The same session copied the `[src:]` convention into six citations of its own and then, at call 58 of 92 and twenty calls after its first edit, wrote the `plan.md` they point at — a back-fill, in hodos's own directory and header format, by a session with no plugin loaded. That raises the bare cost, so it moves the ratio **toward** hodos, which is the direction this item voids. Decision **0159** keeps the run and adds the missing half of the test: a leak voids a run when it moves the multiplier toward hodos **and** its measured magnitude moves the pair's ratio at the two decimals the ratios are published to. Here it does not — 3 454 output tokens against 118 885 in the session and 13.3M in the pair's bare total, 2.2105× against 2.2111× with it removed. These are the figures decision 0159 was taken on, before decision **0166** and 12c-2's review moved pair 1 to 14.21M and 2.52×, and 3 454 tokens is still far below the two decimals — so it is recorded with its bound. A magnitude that cannot be measured at all, like the call-17 read's saving, keeps §6's treatment: the bare number is an upper bound on how cheap bare is.

3. **Every session id is recorded at the moment the session opens.** `scripts/usage.mjs` takes ids, and a session nobody wrote down contributes `missing` rather than tokens. The hodos arm's ids also reach `history.jsonl` through `ledger.mjs` on `Finish`; the bare arm has no ledger, so its ids live only in this file's table.
4. **The enabled plugin set is the same in both arms and is recorded here**, not assumed. On this machine `~/.claude/settings.json` enables ten plugins, and hodos is **not** among them — it reaches a session only through `--plugin-dir`, which is what makes a bare arm possible at all. Two of the ten rewrite reply register from a `SessionStart` hook (`caveman@caveman`, `humanizer@humanizer`), the contamination `BACKLOG.md:38` records for Stage 8's bench runs. The developer chose to **keep them and record the set** rather than change the environment for the measurement: both arms carry the same ten, and the output-token column is read with that stated. What it costs: an output-token count taken under a register instruction is not the count a clean profile would give, and the multiplier is a ratio of two such counts rather than of two clean ones.
5. **The path label is the router's in the hodos arm and the intended one in the bare arm.** §3 and §4 state each task's intended path by filling `FORMATS.md §3`'s nine rows and applying its six verdict rules, with the file count taken as row 1 defines it — every file the change creates or edits, including the test beside each one and the benches that construct the type by literal. Row 3 is read as the specification writes it: adding an *optional* field so that every existing caller stays correct is `no`; adding a required field to a type constructed by full struct literal outside the changed files is `yes`. The hodos arm's router applies the same rows itself and may reach a different verdict; the bare arm has no router, so its label stays the intended one. Both labels are reported per task, T-1's buckets follow the **router's** label, and the asymmetry is stated rather than absorbed: an upgrade in the hodos arm moves a task into the bucket with the looser threshold, which flatters the multiplier, so every upgrade is named in the verdict.

   Review 1 measured the first version of §3 against these rows and found four of ten labels wrong — a new field on `DocScope` breaks four full-struct literals including one in another crate, and the cursor tasks reach four and five files through their benches. The tables below are the re-filled version: the tasks whose rows give `standard` are in §4, and the `quick` arm is the set whose rows actually give `quick`.
6. **Four costs sit outside the multiplier**, each under its own heading with its own figure: the crate extraction of decision **0142** (§5), the fact-threading prerequisite **S0** (§4), Stage 9b's live cross-repository node (§9), and the advisor-hook repair the first run forced (§5, *A second repair*) — the fourth was not foreseen when this list said three, and it is here rather than absorbed because it changed the project mid-measurement.
7. **What the numbers are read against.** T-1's multiplier carries the two thresholds `DESIGN.md §11` and `§13` set as hypotheses: `quick` **≤1.3×** bare Claude, `standard` **≤2×**. They are thresholds and the multiplier is measured against them — so, in `BENCH.md`'s vocabulary, the multiplier is the one number in this file that is *thresholded*. It is a **reported price** and not an acceptance criterion (decision **0158**): `README.md` claims *Frugal* as context discipline and never as a cost win over a bare session, so a ratio against bare Claude cannot be what accepts or rejects the system. It is not a **gate** either: a miss is reported with its numbers and corrects the threshold at 12d by decision (`DESIGN.md §13`'s own heading is *hypotheses, corrected by the pilot*), it does not fail the stage. Every other number here — the shape of what each arm shipped (item 10), findings caught before human review, tests added per task, the digest share, the hold-out score, each run's cost — is a plain measurement with no threshold anywhere.
8. **What each arm reads is part of what is measured.** *(The loader half of this item is false, and §12 corrects it from `PLATFORM-NOTES.md` fact 59: the platform's loader loaded the rules into the ten runs' bare halves too.)* A hodos project has `.claude/rules/*.md` and a bare session has no rule loader, so on any task whose files a rule's `paths:` cover, the hodos arm receives that rule — its instruction, its precedents and its migration list — and the bare arm does not. 9. **A task is finished at the same objective bar in both arms** (decision **0156**). `cargo nextest run --workspace` green, `cargo clippy --workspace --all-targets --all-features -- -D warnings` green, the commit accepted by the project's own `commit-msg` hook, and the developer's acceptance of the change. The hodos arm's review, verify and mutation phases are counted **inside its own cost** and are not a second bar the bare arm has to clear: they are the treatment, not the finish line. The bar binds the **bare** arm — the hodos arm's own red loops and verify already require both commands green — so it raises the denominator and lowers the multiplier, which is the direction that flatters hodos and the opposite of item 2's arrangement for the shares. Stated in §6 with the other things this pilot does not measure. A task that cannot reach the bar is recorded unfinished, with its cost and its reason, rather than dropped. **The bar is run inside the arm's own session**, which pair 3's bare half did not do — it ran one crate's tests and one crate's clippy and stopped when it judged itself done, and the builder ran the workspace pair afterwards. That is the very thing this item exists to remove, so from pair 4 on the bare session runs both workspace commands itself before it is finished.

10. **A third number: the shape of what each arm shipped** (decision **0158**, defined here before the last six runs and read in §10). The cost ratio compares prices and the second number counts what hodos caught in its own work; neither looks at the code. This one does, and it costs no model call, because the pilot project is itself an architecture-analysis tool. Per run, at the arm's branch base and at its merged tip: `ariadne fitness check` — forbidden-dependency violations and cycles, with `ok` and the violation count; `ariadne api-diff <base>..<tip>` — the public surface the range added, removed and changed with its SemVer classification, which takes a ref range and so needs no checkout; and `ariadne query` over `complexity`, `coupling_report`, `weak_spots` (cycles ∪ god-modules ∪ dead-code top-N) and `refactor_suggestions`, each against an index built at that point. Reported as a delta per run and beside its pair, never summed across pairs, with the base's absolute values printed beside every delta so a zero reads as a zero rather than as a measurement that did not run.

    Two limits, written here rather than after the numbers. The arms of a pair do **different tasks** — pair 1 capped `api_surface_diff` in the hodos arm and `fitness_report` in the bare one — so this compares the shape of one task's answer with the shape of another's and rests on the pairing's claim of comparable size exactly as the cost ratio does. And the six assertion-message tasks are expected to read **zero on both arms**: one test file, no new module, no widened type. A flat result is a finding about §3's task selection, not a failed measurement.

## 4. The `standard` arm — five pairs, exact parse facts and one bound that has to be threaded

## 5. The crate extraction — decision 0142, outside the multiplier

`ariadne-scip` leaves the workspace into a repository of its own. Chosen at 12c-1's Start by the reading in `docs/stages/12c1-plan.md §4` and named in decision **0142**'s *Applied in*: a leaf with one consumer inside the workspace (`ariadne-cli`, three items), needing `ariadne-core` for a single enum, that carries the whole protobuf surface — `prost`, `prost-types`, and in `[build-dependencies]` `prost-build` plus `protoc-bin-vendored`, which ships `protoc` bytes every build of the workspace pays for. **The sentence:** *a SCIP ingester follows an external index schema and vendors a compiler to read it, and it is a leaf with one consumer — so it belongs beside that schema's cadence and not inside a workspace whose every build carries its `protoc`.*

**The shape of the second repository changed twice, and the reason is a defect this part shipped.** It began as a local bare clone beside the checkout, the arrangement `bench/scripts/pair-seed.mjs` seeds for the fixture pair, with the workspace reaching the crate by a path into its sibling directory. Review 1 measured what that costs: a path to a sibling of the repository root resolves on one disk and nowhere else, so `git archive HEAD | tar -x` into a scratch directory followed by `cargo metadata --no-deps --offline` exited **101** — *failed to load manifest for dependency `ariadne-scip`* — and every cargo job in `.github/workflows/ci.yml` (`fmt`, `clippy --workspace`, `nextest run --workspace`, `deny check`, `audit`, `doc --workspace`, `bench --no-run`, `build --workspace`, the architecture test) would have failed at manifest load after a bare checkout. Nothing had been pushed since the split, so CI had not yet said so.

The repair, at `3cc5404` and `8b307eb`: the crate lives in **`mind-decay/ariadne-scip`**, public, and takes `ariadne-core` from `mind-decay/Ariadne` by git url; the workspace's root manifest patches that url onto its own `crates/ariadne-core`, so the composition root links **one** core and one `ScipFacts` rather than two. Both repositories are public — the crate's code and its whole history were already public inside `Ariadne` — so a bare checkout resolves the dependency with no credential, which is what keeps CI green and is why the private repository the pair started with was published rather than paired with a CI secret. Verified: `cargo metadata` on a fresh `git archive` copy exits **0**, and a cold `cargo nextest run --workspace` after `cargo clean` is **515 passed, 23 skipped** in 3m02s total (1m45s of it the rebuild).

**Which `ariadne-core` each green run used**, because they are not the same one. The workspace's run links the local `crates/ariadne-core` at `8b307eb` — `cargo metadata` reports exactly **one** `ariadne-core` in the graph, `source: null`, which is the `[patch]` doing its work. ## 8. The duplicate pairs — the same task in both arms (decision 0160)

The ten runs of §3 measured cost and nothing about the work, because item 1 sends each task to exactly one arm. The five pairs of §4 are run the other way: **one task, both arms, from the same base**. Fixed here before the first duplicate runs.

**The protocol, per pair.**

1. **The base is one commit**, the current `hodos-pilot` tip, recorded in the pair's row before either arm starts.
2. **The bare arm runs first**, in a clone made for the task and thrown away after it is measured: `git clone` the pilot to a directory outside it, branch from `<base>`, then remove **exactly what `init` wrote** — `.claude/rules/`, `.claude/hodos/` and `CLAUDE.md`'s `<!-- hodos:begin -->` block — commit that as the branch's base so it is outside every measured diff, and `ariadne index` so the MCP tools answer (decision **0161**). What stays is the project as it was before hodos: `.claude/plans/`, `.claude/hooks/`, `.claude/settings.json`, `.mcp.json` and `CLAUDE.md`'s own ARIADNE block. `.claude/settings.local.json` is **untracked** (`git ls-files .claude` returns `hodos/config.json`, two hooks, 222 plan files, seven rules and `settings.json`), so a clone carries none and the control session starts with no stored approvals — option (c)'s effect arrives by construction rather than by choice, and it is recorded here rather than counted as a decision. The treatment under test is hodos and nothing else in that tree is hodos; taking the ariadne MCP server away from the control would measure *with ariadne against without ariadne* on top of it, and would move all three readings below in hodos's favour for a reason that is not hodos. That is the control the ten runs did not have: all three `quick` bare halves read hodos's rules unprompted because the files were in the tree, and two of the three also read `commit-scope.md`. It also means these five pairs and §3's ten are **not the same control** and are not comparable on that axis, which each pair's row says.
3. The bare session gets the task description and the stop bar of item 9 — both workspace commands green, the commit written by the session — and nothing else. Its branch is measured and then discarded; nothing from the clone is merged.
4. **The hodos arm runs second**, in the pilot, from the same base, `/hodos:task` → `/hodos:run`. Its branch merges as real work.
5. Order is bare-first for isolation, not for cost: the two arms work in separate trees from one commit, so neither can inherit from the other, and item 2's *hodos pays first* has nothing to order.
6. Both halves' costs are `usage.mjs` over their session ids, and both halves' engine time is the session span to its last assistant message less the **developer's** time — every `AskUserQuestion` wait from its call to its answer, plus the gap before each message a person typed (decision **0164**, which replaced a rule that subtracted every gap over 90 seconds and so removed the engine's own waits on commands and subagents as if they were the developer's).
7. **Both arms of a pair run on one model** (decision **0163**): the session default when each arm starts, not pinned, with `message.model` read from both arms' transcripts and from every subagent the hodos arm dispatched. A pair whose two main models differ is re-run, not read. The default moved between D1's arms — M11 ran on `claude-opus-5` on 2026-09-13, the default was `claude-opus-5-5` before M12 started — so D1's bare arm was re-bought on the new one, and the first run is kept beside the pair as a measurement of what the model alone moves on the bare arm. The five pairs therefore run on `claude-opus-5-5` where §3's ten ran on `claude-opus-5`: a second axis, beside item 2's control tree, on which the two sets are not comparable.

**The three readings, per pair.**

- **Cost, same task.** hodos ÷ bare over one task rather than over two tasks argued to be comparable — the number §3's pairs could only approximate.
- **Structure** (decision **0158**, item 10): fitness violations, public surface added/removed/changed, complexity, coupling, dead code and refactor candidates, at the base and at each arm's tip. On one task the two deltas are attributable to the arm.
- **The blind rubric.** Both diffs squashed, no commit messages, no branch names, labelled A and B with the order randomised per pair, given to a **fresh general-purpose agent** that is not told hodos exists and is not one of the `hodos-*` agents. Six criteria, each scored on both diffs with a stated reason and ranked separately rather than rolled into one verdict:

  | Criterion | The question put to the judge |
  |---|---|
  | where the change lives | Is each piece in the layer it belongs to, and did the public contract widen more than the task required? |
  | case coverage | Which edge cases does the change name and handle — empty, zero, overflow, absent, ambiguous — and which does it leave? |
  | code quality | Duplication, naming, error handling, the shape of the API a caller sees. |
  | test strength | Does a test pin behaviour or restate the implementation, and would it fail if the logic were wrong? |
  | recorded reasoning | What can a later reader reconstruct from the diff alone about why it is this way? |
  | scope discipline | What was done beyond the task, and what was left undone? |

Where structure and rubric disagree, the disagreement is published. A flat result — the judge cannot separate the arms — is a finding about what this size of task can show, not a failed measurement.

**What this costs the project.** Five of §4's ten tasks are not done by anyone: the wrapper-family captures, the C family, `go.scm`/`csharp.scm`, the `search_code` / `list_symbols` cursor, and `doc_for`'s cursor and concise mode. Their rows stay in §4 as unrun.
