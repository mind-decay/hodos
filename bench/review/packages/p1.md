# Plan — orders-summary-row
Path: standard · Type: feature · Tasks: 3

## Goal
A summary line above the order list: how many orders the current filter matches, what they add up to, and the three largest.

## Non-goals
Server-side aggregation. A new endpoint. Persisting the summary between sessions.

## Design
### Modules
`features/orders/summary.ts` — the request the summary makes. `features/orders/ui/OrdersSummary.tsx` — the line itself. The ranking helper joins `features/orders/model.ts`, beside the filter store.
### Dependency direction
`ui/` imports `summary.ts` and `model.ts`; neither imports `ui/`. Nothing outside `features/orders` imports any of the three.
### Interfaces
`fetchSummaryOrders(status: string): Promise<Order[]>` · `topByTotal(orders: Order[], count: number): Order[]` · `<OrdersSummary status={status} />`
### Invariants & failure modes
The summary renders nothing until its data has arrived. A failed request leaves the list alone: the summary is an addition, and the list's own error surface stays the one the page shows.
### Data & scale
The filtered list is at most a few hundred rows — the endpoint returns the whole collection today — so the totals are added in the browser.
### Precedent
`src/features/orders/ui/OrdersPage.tsx` for a query in a component; `src/features/orders/api.ts` for where a feature's keys and requests live.
### Refactor in scope
The feature's key factory gains the summary's key. Nothing else moves.
### External APIs
TanStack Query v5 `useQuery`, as `OrdersPage` already calls it.
### Architecture alternatives
Deriving the totals from the list page's own query result would need no request at all, and was declined for this task because the summary is specified to hold while the list is paging — a decision to revisit when paging lands.

## Tasks
### T1. The summary request
Files: `src/features/orders/summary.ts`. Acceptance: the function returns the orders for a status.
### T2. The ranking helper
Files: `src/features/orders/model.ts`. Acceptance: `topByTotal` returns the `count` largest orders, largest first.
### T3. The summary line
Files: `src/features/orders/ui/OrdersSummary.tsx`, `src/features/orders/api.ts`. Acceptance: the line shows the count and the total for the current filter, and renders nothing before the data arrives.
