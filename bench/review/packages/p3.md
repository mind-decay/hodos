# Plan — order-actions
Path: standard · Type: feature · Tasks: 3

## Goal
Two actions on an order: mark it paid, and cancel it. Both report while they run and say what went wrong when they fail.

## Non-goals
Optimistic updates. Undo. Any change to the list page.

## Design
### Modules
`features/orders/ui/OrderActions.tsx` — the buttons and their failure surface. `features/orders/ui/useCancelOrder.ts` — the cancel call and the flag that reports it is running.
### Dependency direction
Both reach the network through `src/lib/http`. Nothing in `lib/` learns about orders.
### Interfaces
`<OrderActions orderId={id} />` · `useCancelOrder(order: Order | undefined): { busy: boolean; cancel: () => Promise<void> }`
### Invariants & failure modes
The busy flag is true exactly while a call is in flight — every path out of `cancel` leaves it false. A failed call leaves the order as it was and puts the reason on the page.
### Data & scale
One order at a time. No collection.
### Precedent
`src/features/orders/ui/OrderDetailPage.tsx` for the detail page's shape and its error surface; `src/lib/http.ts:9` for the client.
### Refactor in scope
Nothing outside `features/orders/ui`. The list's own tests may gain the case for the totals it already formats.
### External APIs
None beyond the client.
### Architecture alternatives
Putting both actions in the detail page directly was declined: the page already holds the query, and a component that owns its own failure surface is the shape the list page set.

## Tasks
### T1. The actions component
Files: `src/features/orders/ui/OrderActions.tsx`. Acceptance: pressing "Mark paid" calls the endpoint; a failure puts the message on the page where a screen reader announces it.
### T2. Cancel, with its running flag
Files: `src/features/orders/ui/useCancelOrder.ts`. Acceptance: `busy` is true while the call runs and false on every path out of it, including the one where there is no order yet.
### T3. Cover the actions
Files: `src/features/orders/ui/OrderActions.test.tsx`, `src/features/orders/ui/OrderList.test.tsx`. Acceptance: a failing call renders its message; the list's totals keep their two decimals.
