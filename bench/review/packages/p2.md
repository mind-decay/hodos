# Plan — status-in-the-url
Path: standard · Type: feature · Tasks: 3

## Goal
A filtered order list can be linked to: `/orders?status=paid` opens on that filter, and the home page says which filter is in effect.

## Non-goals
Writing the filter back into the URL as the user changes it. Any other query parameter.

## Design
### Modules
`features/orders/ui/useStatusParam.ts` — the URL half. `features/home/ui/HomePage.tsx` — the line that names the filter. `features/orders/api.ts` — the failure message the list shows.
### Dependency direction
`features/home` reaches `features/orders` through the feature's public surface, the way every other cross-feature import in this application does.
### Interfaces
`useStatusParam(): StatusFilter`
### Invariants & failure modes
A URL that asks for a status the application does not have falls back to `all` rather than rendering an empty list with no explanation. A list request that fails reaches the page as a message a person can read.
### Data & scale
Four possible values, from `StatusFilter`. No storage.
### Precedent
`src/features/orders/model.ts:3` for the union; `src/features/home/ui/HomePage.tsx` for the page's shape.
### Refactor in scope
`features/orders/api.ts`'s list call, for the failure message. The shared client's own tests may gain the case for the `accept` header it already sends.
### External APIs
`useSearchParams` from react-router-dom v6, which the application already routes with.
### Architecture alternatives
Holding the status in the zustand store alone was the shape before this task; it cannot be linked to, which is the goal.

## Tasks
### T1. The status parameter
Files: `src/features/orders/ui/useStatusParam.ts`. Acceptance: a known status in the URL is returned; an unknown one falls back to `all`.
### T2. The filter on the home page
Files: `src/features/home/ui/HomePage.tsx`. Acceptance: the home page names the filter currently in effect.
### T3. A readable failure for the list
Files: `src/features/orders/api.ts`, `src/lib/http.test.ts`. Acceptance: a failed list request reaches the page with a message naming what failed.
