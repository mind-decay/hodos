# Plan — orders-list-polish
Path: standard · Type: refactor · Tasks: 3

## Goal
The list page can refresh itself, and the rows it shows follow the status filter without going through the page's query.

## Non-goals
Changing the shared HTTP client. Changing what the list renders.

## Design
### Modules
`features/orders/ui/OrderRefresh.tsx` — the refresh control. `features/orders/ui/useOrdersByStatus.ts` — the rows for one status.
### Dependency direction
Both live under `features/orders/ui` and reach the network the way every other caller does.
### Interfaces
`useOrdersByStatus(status: string): Order[]` · `<OrderRefresh />`
### Invariants & failure modes
The rows on screen are the rows for the status currently selected — a response for a status the user has already left never replaces them.
### Data & scale
The same few hundred rows the list page already holds.
### Precedent
`src/features/orders/ui/OrdersPage.tsx:10` for how this feature fetches a list; `src/lib/http.ts:9` for the client every caller uses.
### Refactor in scope
`features/orders/ui` and the feature's own `features/orders/api.ts`, where its requests live. In `src/lib` a comment may be added where one is missing; no file there changes behaviour, in either direction.
### External APIs
None beyond the client.
### Architecture alternatives
Calling `refetch()` on the page's existing query would reuse the cache and was declined here because the refresh control is specified to work from anywhere on the page, including before the list query has been created.

## Tasks
### T1. The refresh control
Files: `src/features/orders/ui/OrderRefresh.tsx`. Acceptance: pressing it reloads the orders and the count it shows changes with them.
### T2. Rows for one status
Files: `src/features/orders/ui/useOrdersByStatus.ts`, `src/features/orders/api.ts`. Acceptance: changing the status twice in quick succession leaves the rows for the status that was selected last.
### T3. The client's own nuance
Files: `src/lib/errors.ts`. Acceptance: the fallback message's reason is written where the fallback is.
